使い方とよくある質問

  1. 上の枠にExcel（.xlsx/.xlsm）ファイルをドラッグ＆ドロップするか、クリックして選びます。
  2. 「参照先ファイル一覧」で、ブックが外部のどのファイルを参照しているか（パスとシート名）を確認します。
  3. 「発生箇所の一覧」で、その参照が数式・名前定義・入力規則・条件付き書式・グラフのどこで使われているかを確認します。
  4. 必要な一覧を「CSVでダウンロード」で保存します（絞り込んだ内容がそのまま書き出されます）。

Q. 「データ」タブの「リンクの編集」を押してもリンクの場所が分からないのはなぜですか？

A. Excelの「リンクの編集」ダイアログは参照先ファイルの一覧は出ますが、そのリンクがブック内のどこ（どのシートのどのセルか、名前定義か、入力規則か）で使われているかまでは表示しません。このツールはその「使われている場所」を探すためのものです。

Q. このツールにファイルをアップロードしても安全ですか？

A. はい。ファイルはサーバーに送信されず、すべてこのページを開いているブラウザの中だけで読み込み・解析されます（サイト全体の閲覧数をCookieなし・匿名で数えるGoatCounterの通信のみ発生します）。

Q. 対応しているファイル形式は？

A. Excel 2007以降の.xlsx・.xlsm形式に対応しています。古い.xls形式や、パスワードで保護されたファイルは読み込めません。

Q. 「参照先ファイル一覧」のパスが表示されない・不明と出るのはなぜですか？

A. 外部参照の接続情報（どのファイルを指しているか）は、作成時にブックへ保存されますが、ファイルを長期間開かない、または「リンクの編集」で「リンクの解除」をした後にリンク自体だけ残った場合など、保存先の情報が欠けていることがあります。その場合は「不明」と表示し、推測はしません。参照番号（[1]など）と、使われている場所の一覧は欠けていなければ表示されます。

Q. 参照先として出てくるパスは、今もそこにファイルがあることを意味しますか？

A. いいえ。ブックに保存された時点のパスを表示するだけで、実際にそのファイルが今も同じ場所にあるかはこのツールでは確認しません（ネットワーク通信は一切行いません）。

Q. 「数式」「名前定義」「データの入力規則」「条件付き書式」「グラフ」はどうやって判定していますか？

A. それぞれの内容（数式の文字列）を機械的に走査し、「[1]」のような外部ワークブックの参照番号を表す書き方が含まれているかで判定しています。文字列の形だけを見た簡易判定のため、Excelの表（テーブル）機能の列参照「テーブル名[列名]」などとは区別していますが、誤って検出したり、逆に見逃したりすることがあります。

Q. グラフの発生箇所だけ、シート名やセル位置が出ないのはなぜですか？

A. グラフの元データはグラフ自体のファイル（chart1.xmlなど）に保存されており、どのシートに貼り付けられているグラフかをたどる処理は今回のツールでは行っていないため、グラフのファイル名までの表示になります。どの数値軸・系列で使われているかは「数式」欄の文字列で確認してください。

Q. 大きなファイルや多数のファイルは扱えますか？

A. ブラウザのメモリ上で処理するため、発生箇所の合計が数万件程度までを想定しています。一覧の表示は先頭の一定件数のみに制限されることがありますが、ダウンロードするCSVには絞り込み後の全件が含まれます。

How to use & FAQ

  1. Drag and drop Excel (.xlsx/.xlsm) files into the box above, or click it to choose one or more.
  2. Check "External reference targets" to see which outside files the workbook links to (path and sheet names).
  3. Check "Where each link is used" to see whether each reference appears in a formula, a defined name, data validation, conditional formatting, or a chart.
  4. Click "Download as CSV" to save the list — exactly what the filters currently show.

Q. Excel's Data → Edit Links shows the target file, but not where the link is used in the workbook. Why?

A. Excel's Edit Links dialog lists target files but not which sheet, cell, defined name, or validation rule actually uses each link. This tool exists to find exactly that.

Q. Is it safe to use this on my files?

A. Yes. Files are never uploaded to a server — everything is read and analyzed inside your browser (only an anonymous, cookie-free page-view count for this site is sent, via GoatCounter).

Q. Which file formats are supported?

A. Excel 2007+ .xlsx and .xlsm files. The older .xls format and password-protected files are not supported.

Q. Why does the target path show as "unknown" for some references?

A. The connection info (which file a reference points to) is normally stored in the workbook, but it can go missing — for example after "Break Link" was used on a link while leaving the reference itself in a formula. In that case the path shows as unknown rather than guessed; the reference number (like "[1]") and where it's used are still shown as long as those parts remain.

Q. Does the shown path mean the file is still there?

A. No. It only shows the path as it was saved in the workbook at some point; this tool never makes a network request to check whether the file still exists there.

Q. How are "formula", "defined name", "data validation", "conditional formatting" and "chart" detected?

A. Each one's text is scanned for the "[1]"-style external-workbook reference number. This is a simple text-pattern check — it's written to avoid confusing it with Excel Table column references like "TableName[ColumnName]", but it can still over- or under-detect in unusual cases.

Q. Why don't chart entries show a sheet name or cell?

A. A chart's series data lives inside the chart's own file (e.g. chart1.xml); this tool doesn't trace which sheet each chart is embedded in, so charts are listed by their chart file name only. Check the formula text itself for which series or axis is affected.

Q. Can it handle large or many files?

A. Everything runs in browser memory, built for up to roughly tens of thousands of occurrences in total. The on-screen list may be capped for performance, but the downloaded CSV always contains every row matching the current filters.
