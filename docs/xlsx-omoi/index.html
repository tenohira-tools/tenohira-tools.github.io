「エクセルが重い」原因を診断：ファイル内訳チェッカー

Excel(.xlsx/.xlsm)ファイルの容量を、シート・画像・スタイル・共有文字列・ピボットキャッシュなどのパーツ別に内訳表示し、容量を押し上げている可能性が高い原因を順に挙げます。ファイルを開かず、ブラウザの中だけで診断します。

ここにExcel(.xlsx/.xlsm)ファイルをドラッグ＆ドロップ、またはクリックして選択

1回に1ファイル。ファイルは選択した端末の中だけで処理されます。

全体の内訳

「ZIP内サイズ」は.xlsxファイル自体の容量（メール添付などで実感する重さ）に直結する数値です。

容量を押し上げている可能性が高い原因

    数値から機械的に推測した「可能性」であり、断定ではありません。重要なファイルは最終的にExcelの「パフォーマンスをチェック」（Microsoft 365）などでも確認してください。

    使い方とよくある質問

    1. 上の枠にExcel（.xlsx/.xlsm）ファイルをドラッグ＆ドロップするか、クリックして選びます。
    2. 「全体の内訳」でファイル容量に占める大まかな構成と、スタイルや名前定義などの数を確認します。
    3. 「容量を押し上げている可能性が高い原因」を確認します（スコアが高い順）。
    4. 「パーツ別の容量一覧」で、シートごと・画像・スタイルなどの実際のサイズを細かく確認できます。必要ならCSVでダウンロードできます。

    Q. このツールにファイルをアップロードしても安全ですか？

    A. はい。ファイルはサーバーに送信されず、すべてこのページを開いているブラウザの中だけで読み込みが行われます（サイト全体の閲覧数をCookieなし・匿名で数えるGoatCounterの通信のみ発生します）。ファイルの内容を書き換えたり保存したりすることもありません。

    Q. 「エクセルが重い」原因はどうやって調べていますか？

    A. .xlsxファイルの実体はZIP形式で、内部にシート・画像・スタイル・共有文字列などの部品が別々のファイルとして入っています。このツールはZIPの目次（セントラルディレクトリ）から各部品の実際のサイズを読み取って内訳を作り、さらにシートの使用範囲（Ctrl+Endで飛ぶ場所）・セルの書式（スタイル）の組み合わせ数・テキスト（共有文字列）の種類数・ピボットテーブルのキャッシュの有無などを調べて、容量や動作の重さに関わりやすい箇所を順に挙げます。

    Q. 「使用範囲が実際のデータよりかなり大きい」とはどういう意味ですか？

    A. Excelでは、セルに値や数式・書式を一度でも設定すると、そのセルの情報がファイル内に保存され続けます。行や列を選択してまとめて色を塗ったり、コピー＆ペーストの範囲が広すぎたりすると、実際にデータが入っているのはごく一部でも、Ctrl+Endで飛ぶ場所（使用範囲）だけがどんどん遠くに広がっていきます。このツールは、使用範囲の広さに対して実際に値・数式・書式を持つセルの数が極端に少ないシートを検出して知らせます。該当するシートは、Ctrl+Endで飛んだ場所から下・右の余分な行や列を選択して削除すると、ファイルが軽くなることがあります。

    Q. セルスタイル（書式の組み合わせ）の数が多いと何が問題ですか？

    A. フォント・色・枠線・数値の表示形式などの組み合わせ1つごとに「セルスタイル」が1つ登録され、ファイル内に保存されます。コピー＆ペーストを繰り返すたびに似たような組み合わせが新しく増えてしまうことがあり、数が極端に多い（数千〜）と、ファイルを開く・保存する動作が遅くなる原因になりやすいと言われています。断定はしませんが、目安として知っておくと役立ちます。

    Q. ピボットテーブルのキャッシュとは何ですか？

    A. ピボットテーブルは、元になる表のデータをそのままコピーした「キャッシュ」を内部に持っています。元の表とキャッシュの二重でデータを持つため、ピボットテーブルの数が多い・元データが大きいファイルほど容量が大きくなりやすくなります。Excel側で「ピボットテーブルの保存元データをファイルに保存しない（キャッシュを使わない）」設定にすると容量を減らせる場合があります。

    Q. 対応しているファイル形式は？ファイルサイズの上限はありますか？

    A. Excel 2007以降の.xlsx・.xlsm形式に対応しています。古い.xls形式や、パスワードで保護されたファイルは読み込めません。ファイルはブラウザのメモリ上で処理するため、非常に大きいファイル（数百MB以上）では、診断自体に時間がかかったりブラウザが重くなったりすることがあります。

    Q. 結果通りに直せば必ずファイルが軽くなりますか？

    A. このツールは原因の「可能性」を挙げるだけで、ファイルを書き換えることはしません。実際に軽くするには、該当するシートの余分な行・列の削除、使っていない画像やピボットテーブルの整理などをExcel側で行う必要があります。原因が1つに絞れないファイルもあります。

    How to use & FAQ

    1. Drag and drop an Excel (.xlsx/.xlsm) file into the box above, or click it to choose one.
    2. Check the overall breakdown: the rough share of each part, plus counts like cell styles and defined names.
    3. Review the ranked list of likely causes (highest score first).
    4. Use the detailed per-part table (sheets, images, styles, …) for the exact sizes, and download it as CSV if needed.

    Q. Is it safe to use this on my files?

    A. Yes. Files are never uploaded to a server — everything is read inside your browser (only an anonymous, cookie-free page-view count for this site is sent, via GoatCounter). The file's contents are never modified or saved anywhere.

    Q. How does this figure out why a file feels heavy?

    A. An .xlsx file is really a ZIP archive containing separate parts for sheets, images, styles, shared strings, and more. This tool reads the ZIP's central directory to get each part's real size, then also checks each sheet's used range (where Ctrl+End jumps to), the number of distinct cell-style combinations, the number of distinct shared strings, and whether pivot-table caches are present — and ranks the factors most likely to be adding to the size or sluggishness.

    Q. What does "used range is much larger than the actual data" mean?

    A. Once a cell has ever held a value, formula, or formatting, Excel keeps that cell's record in the file. Selecting whole rows or columns to apply a fill color, or pasting into a far larger range than intended, pushes the "used range" (where Ctrl+End jumps) outward even though the actual data stays small. This tool flags sheets where the used range is far larger than the number of cells that actually hold a value, formula or style — deleting the extra rows/columns past where Ctrl+End should land can shrink the file.

    Q. Why would many cell styles be a problem?

    A. Every distinct combination of font, color, border and number format is stored once as a "cell style" in the file. Repeated copy-pasting can keep adding near-duplicate combinations, and a very large count (thousands+) is commonly associated with slower opening and saving — not a certainty, but a useful signal.

    Q. What is a pivot-table cache?

    A. A PivotTable keeps an internal copy ("cache") of the source data it summarizes, so the data effectively exists twice in the file. Many pivot tables, or a large source range, can noticeably inflate file size. Excel's option to not save the source data with the file (rebuild from source on open) can reduce this.

    Q. Which formats and sizes are supported?

    A. Excel 2007+ .xlsx and .xlsm files. The older .xls format and password-protected files are not supported. Everything runs in your browser's memory, so very large files (several hundred MB) may take a while or make the browser sluggish during diagnosis.

    Q. If I act on the results, is the file guaranteed to get smaller?

    A. This tool only reports likely causes — it never modifies your file. Actually shrinking it requires fixing the flagged sheets' extra rows/columns, cleaning up unused images or pivot tables, etc. in Excel itself. Some files don't have one single cause.
