Ctrl+Endで遠くへ飛ぶ・印刷で白紙ページが大量に出るときの「使用範囲」リセット

Ctrl+Endを押すと、データが入っている範囲よりずっと遠いセルまで飛ぶことがあります。これはExcelが「どこかに書式や値が一度でも入った」セルを記憶し続けるためで、印刷すると関係ない白紙のページが何十枚も出たり、保存や起動が遅くなったりする原因になります。このツールはExcel(.xlsx/.xlsm)の全シートを解析し、実際のデータと結合セルの範囲だけに使用範囲を縮小した新しいファイルを書き出します。Excelの「テーブル」機能を使っているシートは、安全のため自動的に対象から外します。元のファイルは変更しません。

ここにExcel(.xlsx/.xlsm)ファイルをドラッグ＆ドロップ、またはクリックして選択

1回に1ファイル。全シートの使用範囲（dimension）とセルを解析します。ファイルは選択した端末の中だけで処理されます。

シートごとの使用範囲

実データより先に書式・値が残っているシートが見つかりました。下のボタンで、使用範囲を縮小した新しいファイルを書き出せます。

どのシートも使用範囲はすでに実データ（と結合セル）の範囲に収まっていました。縮小できる箇所は見つかりませんでした。

注意：実データの外側に、罫線や塗りつぶしなどの書式だけを意図して設定していた場合（将来の入力用に枠を広めに引いていた等）、その部分の書式は削除されます。書き出し後に見た目を確認してください。

シート別の内訳

「記録されている最終セル」は、現在Ctrl+Endを押すと飛ぶ位置に相当します。「実データの最終セル」は、値・数式が入っているセルと結合セルの範囲から計算した、本来の範囲です。差があるシートほど、不要な書式が遠くまで残っている可能性があります。

使い方とよくある質問

  1. 上の枠にExcel（.xlsx/.xlsm）ファイルをドラッグ＆ドロップするか、クリックして選びます。
  2. 自動で解析され、シートごとに「記録されている最終セル」と「実データの最終セル」の差、削除される空行・空セルの数が表示されます。
  3. 内訳を確認し、「使用範囲を縮小したファイルを書き出す」でダウンロードします。元のファイルはそのまま残ります。

Q. なぜCtrl+Endで遠いセルまで飛ぶのですか？

A. Excelは、値や数式が入ったセルだけでなく、一度でも書式（フォント・色・枠線など）を設定したセルや、行・列の高さ・幅を変更した範囲も「使われたことがある」として記憶し続けます。そのセルの値を後から消しても、この記憶は自動では消えません。そのため、実際にデータが入っているのはC10まででも、遠くのセルに一度でも色を塗ったり、行や列を広い範囲で選択して書式を変えたりした履歴があると、Ctrl+Endはそのずっと先まで飛んでしまいます。このツールは、値・数式が実際に入っているセルと、結合セルの範囲だけを数え直し、それより先にある書式だけのセル・行を取り除いて、この記憶（使用範囲）を縮小します。

Q. 印刷で白紙のページが大量に出るのと、どう関係しますか？

A. 印刷範囲を明示的に指定していない場合、Excelはこの「使用範囲」をもとに自動で印刷対象のページを決めます。使用範囲が実データよりはるかに先まで広がっていると、何も印刷されない白紙のページまで印刷対象に含まれてしまい、プレビューや実際の印刷で何十枚もの白紙ページが出る原因になります。使用範囲を実データに合わせて縮小すると、この自動判定も実データの範囲に収まりやすくなります。ただし「ページレイアウト」タブで印刷範囲を明示的に設定している場合は、その設定自体は変更しません。

Q. 見た目は変わりませんか？

A. 値・数式が入っているセルと、結合セルの範囲は一切変更しません。変更されるのは、実データや結合セルより先にある、値も数式も入っていない「書式だけのセル・行」だけです。多くの場合これは単純な作業の跡（広い範囲を選んで色を変えた、行の高さをまとめて変更した等）ですが、実データの外側に意図して罫線や色を設定していた場合（将来の入力用に枠を広めに引いていた等）は、その部分の見た目が失われます。書き出し後に一度見た目を確認することをおすすめします。

Q. Excelの「テーブル」機能を使っているシートはどうなりますか？

A. テーブル（ホーム or 挿入タブの「テーブルとして書式設定」）が設定されているシートは、テーブルの範囲指定を壊さないよう、安全のため自動的に対象から外し、そのシートは変更しません。内訳の一覧に「対象外（テーブル機能）」と表示されます。

Q. 列の幅や非表示の行・列も縮小されますか？

A. いいえ。縮小の対象はセル単位の値・数式・結合セルの範囲だけです。列の幅設定（cols要素）、ウィンドウ枠の固定、シートの表示設定、名前定義や印刷範囲の指定そのものは変更しません。これらが原因で重い・範囲が広く見える場合は対象外です。

Q. 対応しているファイル形式は？

A. Excel 2007以降の.xlsx・.xlsm形式に対応しています。古い.xls形式や、パスワードで保護されたファイルは読み込めません。

Q. 元のファイルは変更されますか？

A. いいえ。読み込んだファイルはブラウザのメモリ上でのみ扱われ、変更後の内容は別の新しいファイルとしてダウンロードされます（ファイル名の末尾に「_使用範囲リセット」を付けます）。元のファイルを直接上書きすることはありません。

Q. このツールにファイルをアップロードしても安全ですか？

A. はい。ファイルはサーバーに送信されず、すべてこのページを開いているブラウザの中だけで読み込み・解析・書き換えが行われます（サイト全体の閲覧数をCookieなし・匿名で数えるGoatCounterの通信のみ発生します）。

How to use & FAQ

  1. Drag and drop an Excel (.xlsx/.xlsm) file into the box above, or click it to choose one.
  2. It's analyzed automatically: for each sheet, the gap between its "recorded last cell" and its "actual data last cell", and how many empty rows/cells will be dropped.
  3. Review the breakdown, then click "Build a resized file" to download it. Your original file is untouched.

Q. Why does Ctrl+End jump to a cell far past my data?

A. Excel remembers any cell that has ever held formatting (font, color, border, etc.) or had its row height / column width changed as "used", not only cells that currently hold a value or formula. Clearing a cell's content later doesn't automatically clear this memory. So even if your real data ends at C10, a one-time color fill or a wide row/column selection far away can push Ctrl+End much further than that. This tool recounts only the cells that actually hold a value or formula, plus any merged-cell ranges, and strips the formatting-only cells and rows beyond that point, shrinking this memory (the "used range").

Q. How does this relate to printing dozens of blank pages?

A. When no print area is explicitly set, Excel decides which pages to print based on this used range. If it extends far past your real data, Excel includes those empty pages in the print job and preview, producing dozens of blank pages. Shrinking the used range to match your real data usually fixes this automatic page detection. An explicitly configured print area (Page Layout tab) is left untouched.

Q. Will this change how my file looks?

A. Cells and merged ranges that actually hold a value or formula are never touched. Only formatting-only cells and rows beyond your real data and merged ranges are removed. This is usually just leftover formatting from selecting a wide range by accident, but if you deliberately formatted cells beyond your data (say, a border drawn wider for future entries), that formatting will be lost. Check the result after downloading.

Q. What about sheets using Excel's Table feature?

A. Sheets with a Table ("Format as Table") are automatically skipped and left unchanged, to avoid breaking the table's range. The breakdown shows them as "skipped (Table)".

Q. Does this also shrink column widths or hidden rows/columns?

A. No. Only the cell-level value/formula/merged-range footprint is affected. Column width definitions, frozen panes, sheet view settings, defined names and any explicit print-area setting are left untouched. If your issue is caused by those instead, this tool won't help.

Q. Which file formats are supported?

A. Excel 2007+ .xlsx and .xlsm files. The older .xls format and password-protected files are not supported.

Q. Is my original file modified?

A. No. The file you load is only ever held in your browser's memory; the result is downloaded as a new file (with "_range-reset" appended to the name). Your original file is never overwritten.

Q. Is it safe to use this on my files?

A. Yes. Files are never uploaded to a server — everything is read, analyzed and rewritten inside your browser (only an anonymous, cookie-free page-view count for this site is sent, via GoatCounter).
