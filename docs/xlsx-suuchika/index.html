「数値が文字列として保存されています」(緑の三角)を列ごと一括で数値に変換

セルの左上に緑の三角マークが出て「このセルの数値は、テキストとして保存されています」と注意される、SUM関数で合計されない、並べ替え・フィルターがおかしい——というときに。Excel(.xlsx/.xlsm)の全シートを横断して、テキストとして保存された数値らしいセルを列ごとに一覧化し、選んだ列だけを数値に変換した新しいファイルを書き出します。郵便番号・社員番号など0から始まるコードの列や、8桁以上の長い数字コードの列は、誤って数値化しないよう既定でチェックを外しています。元のファイルは変更しません。

ここにExcel(.xlsx/.xlsm)ファイルをドラッグ＆ドロップ、またはクリックして選択

1回に1ファイル。すべてのシートを解析します。ファイルは選択した端末の中だけで処理されます。

テキストとして保存された数値らしいセルの集計

数式が入っているセル（キャッシュされた文字列の計算結果を含む）は対象外です。判定は「数字だけ（符号・小数点を含む）で構成された文字列かどうか」の機械的なチェックで、桁区切りのカンマが入った文字列は対象になりません。

列ごとの一覧（シート横断）

数値に変換されたセルは、元の文字列と同じ値の「数値」になります（0始まりだった先頭の0や、見た目の桁数は失われます）。セルの表示形式（書式）が「文字列」のままの場合、変換後も左詰めで表示されることがあります。その場合はExcelで列を選び「標準」などの表示形式に変更してください。数式・他のセルの値や書式は一切変更しません。元のファイルは変更されず、新しいファイルとして書き出されます。

使い方とよくある質問

  1. 上の枠にExcel（.xlsx/.xlsm）ファイルをドラッグ＆ドロップするか、クリックして選びます。
  2. 全シートを横断して、テキストとして保存された数値らしいセルが列ごとに一覧表示されます。郵便番号・社員番号のような0始まりのコード列や、8桁以上の長い数字コードの列は、既定でチェックが外れています。
  3. 数値に変換したい列だけチェックを入れ（または外し）ます。
  4. 「選んだ列を数値に変換したファイルを書き出す」でダウンロードします。元のファイルはそのまま残ります。

Q. このツールにファイルをアップロードしても安全ですか？

A. はい。ファイルはサーバーに送信されず、すべてこのページを開いているブラウザの中だけで読み込み・書き換えが行われます（サイト全体の閲覧数をCookieなし・匿名で数えるGoatCounterの通信のみ発生します）。

Q. どんなセルが「対象」として一覧に出ますか？

A. セルの実体が文字列として保存されている（共有文字列、またはインライン文字列）セルのうち、中身が符号（+/-）・数字・小数点だけで構成されている文字列だけを対象にします。数式が入っているセル（計算結果が文字列のものを含む）は、文字列として保存されているわけではないため対象外です。桁区切りのカンマが入った「12,345」のような文字列や、日付・時刻のような文字列も、数字だけの文字列ではないため対象になりません。

Q. 0から始まるコード列や、長い数字の列が既定で対象外（チェックなし）なのはなぜですか？

A. 郵便番号・社員番号・電話番号・JANコードのように「0始まりの桁」や「長い桁数」が意味を持つ列は、数値に変換すると先頭の0が消えたり、Excelが指数表記で丸めてしまったりして、かえって困ることが多いためです。列の中に1つでも0始まりの2桁以上の数字（例：0123）があれば、または整数部分が8桁以上の数字（電話番号・JANコードなど）があれば、その列は既定でチェックを外しています。必要であれば手動でチェックを入れ直せます。

Q. 変換すると、セルの表示（左詰め・右詰め）はどうなりますか？

A. セルが保持している「書式（スタイル）」自体は変更しないため、表示形式が「文字列」に明示的に設定されている列は、数値に変換した後も左詰めのまま表示されることがあります。その場合はExcelでセルの書式設定を「標準」や「数値」に変更してください。数式での集計（SUM等）や並べ替え・フィルターは、表示形式に関わらず数値として正しく扱われるようになります。

Q. 共有数式でコピーされたセルや、結合セルはどう扱われますか？

A. このツールは数式セルを対象にしないため、共有数式そのものには影響しません。結合セルは、値を保持している左上のセルだけが判定・変換の対象になります（結合の解除は行いません）。

Q. 対応しているファイル形式・元のファイルへの影響は？

A. Excel 2007以降の.xlsx・.xlsm形式に対応しています。古い.xls形式や、パスワードで保護されたファイルは読み込めません。元のファイルはブラウザのメモリ上で読み込むだけで変更されず、結果は新しいファイルとしてダウンロードされます（ファイル名の末尾に「_数値変換済み」を付けます）。選んだ列の対象セル以外は、数式・値・書式・グラフ・画像などすべてそのまま保持されます。

How to use & FAQ

  1. Drag and drop an Excel (.xlsx/.xlsm) file into the box above, or click it to choose one.
  2. Every sheet is scanned for cells whose text content looks like a plain number, listed by column. Columns that contain a zero-padded code (like a postal code) or a long digit string (8+ digits) are unchecked by default.
  3. Check (or uncheck) the columns you want converted to real numbers.
  4. Click "Build a file converted to numbers" to download the result — your original file is untouched.

Q. Is it safe to use this on my files?

A. Yes. Files are never uploaded to a server — everything is read and rewritten inside your browser (only an anonymous, cookie-free page-view count for this site is sent, via GoatCounter).

Q. Which cells show up as candidates?

A. Cells whose stored content is text (a shared string or an inline string) where the text consists only of an optional sign, digits and a decimal point — nothing else. Formula cells (including ones whose cached result is text) aren't included, since their content isn't a stored text constant. A string with a thousands separator like "12,345", or a date/time-looking string, doesn't match either, since it isn't purely digits.

Q. Why are zero-padded or long digit columns unchecked by default?

A. Columns like postal codes, employee numbers, phone numbers or JAN/barcode numbers often depend on a leading zero or an exact digit count that has no numeric meaning. Converting them to real numbers would drop the leading zero or risk Excel rounding a very long number into scientific notation. If any cell in a column starts with a zero followed by another digit (like "0123"), or has an integer part of 8 or more digits, that column is left unchecked by default — you can still check it manually if you want it converted.

Q. What happens to how the cell is displayed (left- vs. right-aligned)?

A. This tool doesn't touch a cell's style, so a column whose number format is explicitly set to "Text" may still display left-aligned after conversion. If that happens, change that column's format to "General" or "Number" in Excel. Either way, the value is now a real number, so SUM and other formulas, sorting and filtering all work correctly regardless of the display format.

Q. What about cells copied via a shared formula, or merged cells?

A. This tool never touches formula cells, so shared formulas are unaffected. For a merged cell, only its top-left cell (which holds the actual value) is checked and converted; merging itself is left as-is.

Q. Which formats are supported, and is my original file changed?

A. Excel 2007+ .xlsx and .xlsm files. The older .xls format and password-protected files aren't supported. Your original file is only ever read into browser memory — the result downloads as a new file ("_数値変換済み" appended to the name). Everything besides the converted cells in the columns you chose — other formulas, values, formatting, charts, images — is carried over unchanged.
