Q. このツールにファイルをアップロードしても安全ですか？

A. はい。ファイルはサーバーに送信されず、すべてこのページを開いているブラウザの中だけで結合されます（サイト全体の閲覧数をCookieなし・匿名で数えるGoatCounterの通信のみ発生します）。

Q. ファイルごとに文字コードが違っても大丈夫ですか？

A. はい。CSV・テキストの文字化け直しツールと同じ判定ロジックで、ファイルごとにUTF-8／Shift_JIS（CP932）／EUC-JP／ISO-2022-JPを個別に自動判定してから結合します。判定がおかしい場合はファイルごとの一覧で手動の文字コードに変更できます。

Q. ファイルによって列の並び順や数が違っても結合できますか？

A. 「見出し名で列をそろえる」がONのときは、見出し名（前後の空白は無視）が一致する列を同じ列として扱い、全ファイルの見出し名を集めた列構成に結合します。あるファイルに無い見出しの列は、そのファイルの行では空欄になります。見出し名が完全に一致しない限り別の列として扱われるため、「氏名」と「名前」のような表記違いは自動では統合されません（必要であれば先に表記をそろえてください）。

Q. 「見出し名で列をそろえる」をOFFにするとどうなりますか？

A. 見出しの判定は行わず、1行目を含めたすべての行を、列の並び順のまま上から順につなげます。列数が異なるファイルが混ざっている場合、足りない列は空欄で埋めます。全ファイルの列構成が完全に同じ順番だと分かっている場合に使う設定です。

Q. 同じ見出し名の列が1つのファイルの中に2つあるとどうなりますか？

A. 同じ見出し名は1つの列にまとめられ、先に出てきた側の値が使われます（後ろの同名列の値は捨てられます）。見出し名が重複しているファイルを結合するときはご注意ください。

Q. 大きなファイルや多数のファイルは扱えますか？

A. ブラウザのメモリ上で処理するため、合計で数十MB程度までを想定しています。非常に大きい場合は表示が遅くなることがあります。

How to use & FAQ

  1. Drag and drop several CSV files into the box above, or click it to choose multiple files (you can also add them one at a time). Each file's character encoding is auto-detected individually.
  2. Choose whether to treat each file's first row as a header (on by default), and whether to prepend a "source file" column.
  3. Check the "Aligned columns" section to see which columns exist in every file and which only appear in some.
  4. Review the merged preview, then click "Merge and download CSV".

Q. Is it safe to use this on my files?

A. Yes. Files are never uploaded to a server — everything is merged inside your browser, on this device (only an anonymous, cookie-free page-view count for this site is sent, via GoatCounter).

Q. Can files use different character encodings?

A. Yes. Using the same detection logic as the CSV/Text Mojibake Fixer tool, each file's encoding (UTF-8, Shift_JIS/CP932, EUC-JP, ISO-2022-JP) is detected independently before merging. You can override the detected encoding per file in the file list if it looks wrong.

Q. Can I merge files whose columns are in a different order or count?

A. When "align columns by header name" is on, columns whose header text matches (ignoring leading/trailing spaces) are treated as the same column, and the merged result uses the union of all header names seen across every file. A file missing a given column just gets a blank cell for it in its rows. Since matching requires an exact header match, differently-worded headers (e.g. two words meaning the same thing) are not merged automatically — normalize the wording first if needed.

Q. What happens if I turn off "align columns by header name"?

A. No header matching is done — every row, including the first row of each file, is appended in column order as-is. If files have different column counts, short rows are padded with blank cells. Use this only when you know every file has exactly the same column order.

Q. What if one file has the same header name twice?

A. Duplicate header names are collapsed into a single merged column, keeping the value from whichever one comes first in that row and discarding the other.

Q. Can it handle large or many files?

A. Everything runs in browser memory, so it's built for a combined size of up to tens of megabytes. Very large inputs may make the page slower.
