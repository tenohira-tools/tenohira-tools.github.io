ピボットテーブルのフィルターに古い項目が残るときの、キャッシュ削除ツール

ピボットテーブルのフィルター（抽出）に、元データからもう削除したはずの古い項目が表示され続けるのは、Excelの「保持する項目の数」設定が既定の「自動」のままだからです。さらにピボットテーブルは元データを「キャッシュ」としてファイル内部に複製しており、元の表の行や表自体を削除してもこのキャッシュは残り続けます。Excel(.xlsx/.xlsm)ファイル内のピボットキャッシュを解析し、残っている件数・ユニーク項目数を一覧表示。選んだキャッシュを空にし、「保持する項目の数」を「なし」に設定した新しいファイルを書き出します。元のファイルは変更しません。

ここにExcel(.xlsx/.xlsm)ファイルをドラッグ＆ドロップ、またはクリックして選択

1回に1ファイル。ファイル内の全ピボットキャッシュを解析します。ファイルは選択した端末の中だけで処理されます。

ピボットキャッシュの集計

「レコード数」は元データの行をファイル内部に複製した件数、「ユニーク項目数」はフィルター（抽出）の候補として保存されている値の種類数です。どちらも元データを削除・更新しただけでは減りません。

ピボットキャッシュの一覧

選んだキャッシュの中身（レコード・フィルター候補の値）を空にします。ピボットテーブルの見た目（画面に表示されているグリッド）はシート側に別途保存されているため、このツールでは変わりません。書き出したファイルをExcelで開き、「データ」→「すべて更新」を行うと、現在の元データを使って作り直されます（元データをすでに削除済みの場合は空の表示になります）。元のファイル自体は変更されません。

使い方とよくある質問

  1. 上の枠にExcel（.xlsx/.xlsm）ファイルをドラッグ＆ドロップするか、クリックして選びます。
  2. ファイル内の各ピボットキャッシュについて、使われているピボットテーブル・元データの範囲・残っているレコード数・ユニーク項目数・「保持する項目の数」の現在値が一覧表示されます。
  3. 空にしたいキャッシュにチェックを入れます（「データが残っているものだけ選択」で一括選択も可能）。
  4. 「選んだキャッシュを空にしたファイルを書き出す」でダウンロードします。元のファイルはそのまま残ります。

Q. フィルターのドロップダウンに、もう無いはずの古い項目（取引先名・担当者名など）が表示されたままなのはなぜですか？

A. ピボットテーブルの「保持する項目の数」（フィールドの設定 → データタブ）が既定値の「自動」になっていると、元データから行を削除して更新しても、フィルターの候補一覧からは古い値が自動では消えません。この設定が「自動」または具体的な数の場合、消えたはずの値がファイルの中の「キャッシュ」に残り続け、フィルターを開くたびに表示されてしまいます。

Q. 「ピボットキャッシュ」とは何ですか？

A. ピボットテーブルは、集計のたびに元データを読み直さずに済むよう、元になった表のデータを「キャッシュ」としてファイル内部に複製して保存しています。このキャッシュは、元の表の行を削除したり、元の表自体をシートから削除したりしても、ピボットテーブルを更新しない限りファイルの中に残り続けます。社外にファイルを渡す場合、削除したはずの数値や個人名がこのキャッシュの中に残っている可能性があります。

Q. このツールは何を削除しますか？

A. 選んだピボットキャッシュの「レコード」（複製された元データの行）と「ユニーク項目」（フィールドごとのフィルター候補の値一覧）を空にします。あわせてチェックを入れた場合は、「保持する項目の数」を「なし」に設定し、今後は更新のたびに最新の元データだけがキャッシュされるようにします。ピボットテーブル自体・レイアウト（行・列・値の配置）・他のシートやセルの値は変更しません。

Q. 書き出したファイルを開いても、ピボットテーブルの表示が変わらないのはなぜですか？

A. Excelの画面に表示されているピボットテーブルの集計結果は、キャッシュとは別に、シート自体に通常のセルの値として保存されているためです（画面の見た目はキャッシュを空にしただけでは変わりません）。「データ」タブの「すべて更新」を行うと、空にしたキャッシュに現在の元データが読み込まれ、画面の表示もそのタイミングで更新されます。元データをすでに削除済みの場合は、更新後に空の集計として表示されます。

Q. 「保持する項目の数」を「なし」に設定すると、何か困ることはありますか？

A. 基本的にはありません。「なし」は、更新したときに元データに存在する値だけをフィルターの候補に残す設定で、Excel自身の推奨設定でもあります。元データに一時的に存在しない値を後からフィルターで選べるようにしておきたい、という特殊な使い方をしている場合のみ影響がありますが、通常の集計用途では問題ありません。

Q. 複数のピボットテーブルが同じキャッシュを共有している場合はどうなりますか？

A. 一覧にはキャッシュ単位（ファイル内部で実際に複製されているデータの単位）で表示され、それを使っている全ピボットテーブルの名前とシート名を合わせて表示します。1つのキャッシュを空にすると、それを使っている全ピボットテーブルに影響します（レイアウトは変わらず、キャッシュの中身だけが空になります）。

Q. このツールにファイルをアップロードしても安全ですか？

A. はい。ファイルはサーバーに送信されず、すべてこのページを開いているブラウザの中だけで読み込み・書き換えが行われます（サイト全体の閲覧数をCookieなし・匿名で数えるGoatCounterの通信のみ発生します）。

Q. 対応しているファイル形式は？

A. Excel 2007以降の.xlsx・.xlsm形式に対応しています。古い.xls形式や、パスワードで保護されたファイルは読み込めません。また、外部データ接続・複数範囲の統合・シナリオを元にしたピボットキャッシュは、レコードやフィルター候補の内容が異なる形で保存されているため、このツールでは一覧に表示されますが対象外（空にできません）と案内します。

How to use & FAQ

  1. Drag and drop an Excel (.xlsx/.xlsm) file into the box above, or click it to choose one.
  2. Each PivotCache in the file is listed with the PivotTable(s) using it, its source range, the record count and unique-item count still cached, and the current "items to retain" setting.
  3. Tick the caches you want emptied ("Select caches with leftover data" selects them in bulk).
  4. Click "Build a file with the selected caches emptied" to download the cleaned copy — your original file is untouched.

Q. Why do old items (a former client's name, an ex-employee) still show up in the filter dropdown after I deleted them from the source data?

A. A PivotTable's "Number of items to retain per field" setting (PivotTable Options → Data) defaults to Automatic. With that setting, refreshing after deleting source rows doesn't clear old values out of the filter's candidate list — they stay cached inside the file and reappear every time you open that filter.

Q. What is a "PivotCache"?

A. So it doesn't have to re-read the source data for every calculation, a PivotTable keeps its own copy of that data inside the file, called a cache. That cache stays in the file — even after you delete rows from, or entirely delete, the original source table — until the PivotTable is refreshed. If you hand the file to someone outside your company, numbers or names you thought you'd deleted may still be sitting in that cache.

Q. What exactly does this tool remove?

A. For each PivotCache you select, it empties the "records" (the duplicated source rows) and the "unique items" (the per-field list of filter candidates). If you also leave the checkbox ticked, it sets "items to retain" to None so future refreshes only ever cache what's currently in the source. The PivotTable itself, its layout (rows/columns/values), and every other sheet and cell are left untouched.

Q. Why doesn't the PivotTable's on-screen display change after I open the downloaded file?

A. What you see on screen is a separate, ordinary set of cell values already saved on the sheet itself — not read live from the cache. Emptying the cache doesn't touch that. Running Data → Refresh All rebuilds the cache from the current source data and updates the on-screen display at the same time (showing an empty result if the source has since been deleted).

Q. Is there any downside to setting "items to retain" to None?

A. Generally no — it's Excel's own recommended setting, and it simply means the filter's candidate list only ever shows values that currently exist in the source after a refresh. It only matters if you deliberately rely on being able to filter by a value that's temporarily missing from the source, which is an unusual workflow.

Q. What if several PivotTables share the same cache?

A. The list shows one row per actual cache (the underlying duplicated-data unit), together with the names and sheets of every PivotTable using it. Emptying one cache affects every PivotTable that shares it (their layout is untouched — only the cache contents are cleared).

Q. Is it safe to use this on my files?

A. Yes. Files are never uploaded to a server — everything is read and rewritten inside your browser (only an anonymous, cookie-free page-view count for this site is sent, via GoatCounter).

Q. Which file formats are supported?

A. Excel 2007+ .xlsx and .xlsm files. The older .xls format and password-protected files are not supported. PivotCaches built from an external data connection, consolidated ranges, or a scenario store their records differently, so they're listed but marked as not supported for emptying.
