      使い方とよくある質問

      1. 上で「変換後の形式」を選びます（西暦の数字表記／西暦の漢字表記／和暦漢字／和暦の略記）。
      2. 「文章」モードでは、文章を貼り付けて「変換する」を押すと、見つかった日付だけをその場で指定の形式に書き換えます。「CSVファイル」モードでは、CSVをドラッグ＆ドロップすると全セルを対象に同じ処理をしてプレビューし、ダウンロードできます。
      3. 対応する表記：「令和6年1月2日」のような和暦の漢字表記（元年も可）、「R6.1.2」「H31/4/1」のような元号の略記（M/T/S/H/R）、「2024/1/2」「2024-01-02」のような西暦のスラッシュ・ハイフン区切り、「2024年1月2日」のような西暦の漢字表記。
      4. 平成31年5月1日のように、元号の境目を越えて実在しない日付は変換せず、その場に残したうえで「検出した日付」に理由つきで表示します。

      Q. なぜ「令和1年3月1日」のような日付は変換されないのですか？

      A. 令和は2019年5月1日に始まった元号なので、それより前の日付には使えません（2019年3月1日は平成31年にあたります）。同様に「平成31年5月1日」も、平成が2019年4月30日までしかないため実在しません。このツールは元号の開始日・終了日をもとに存在しない組み合わせを検出し、正しく直せない場合は黙って変換せず、そのまま残してお知らせします。

      Q. 「2024/13/40」のような日付はどうなりますか？

      A. 実在しないカレンダー上の日付（13月や、その月に無い日にちなど）も同様に変換せず、「検出した日付」に理由（存在しない日付）を添えて表示します。うるう年の2月29日は、実際にうるう年である年だけ正しく変換されます。

      Q. すべての日付表記を見つけられますか？

      A. いいえ。誤検出を避けるため、西暦のスラッシュ・ハイフン区切り（2024/1/2など）は西暦が1900〜2099の範囲にあるものだけを対象にしています。伝票番号や商品コードのような日付に似た数字の並びを誤って変換しないための制限です。元号の略記（R150.1.1のように年数が極端に大きいものなど）も対象外です。変換前にプレビューまたは検出リストで、意図しない箇所が変換されていないか確認してください。

      Q. 文章やファイルはサーバーに送信されますか？

      A. いいえ。貼り付けた文章やアップロードしたファイルはサーバーに送信されず、すべてこのページを開いているブラウザの中だけで処理されます（サイト全体の閲覧数をCookieなし・匿名で数えるGoatCounterの通信のみ発生します）。

      Q. CSVモードで、見出し行やIDの列も変換されてしまいませんか？

      A. 見出し（1行目）は「1行目を見出しとして扱う」を付けたままにすると変換対象から外れます。データの列については、セルの中に日付らしい表記が見つかった場合だけ書き換えます。上記の誤検出対策はありますが、完全ではないため、ダウンロード前にプレビューで確認してください。

      How to use & FAQ

      1. Choose an output format above (numeric Western date, kanji Western date, kanji Japanese-era date, or abbreviated Japanese-era date).
      2. In "Text" mode, paste text and click "Convert" — only the dates it finds are rewritten, in place. In "CSV file" mode, drop a CSV file and the same detection runs on every cell, with a preview and download.
      3. Formats it recognizes: kanji-era dates like 令和6年1月2日 (including 元年 for year 1), abbreviated era dates like R6.1.2 or H31/4/1 (M/T/S/H/R), slash/hyphen Western dates like 2024/1/2 or 2024-01-02, and kanji Western dates like 2024年1月2日.
      4. A date that doesn't actually exist — for example one that crosses an era boundary — is left unchanged and listed, with a reason, under "Dates found".

      Q. Why isn't "令和1年3月1日" (Reiwa 1, March 1) converted?

      A. The Reiwa era began on 2019-05-01, so no date before that can be "Reiwa" — 2019-03-01 actually falls in Heisei 31. Likewise "Heisei 31, May 1" doesn't exist either, since Heisei ended on 2019-04-30. This tool checks each era's real start and end dates and never guesses when a combination doesn't exist — it leaves it untouched and flags it instead.

      Q. What about a date like "2024/13/40"?

      A. A date that isn't real on the calendar (month 13, a day that doesn't exist in that month) is likewise left unchanged and flagged as invalid. February 29 only converts correctly in an actual leap year.

      Q. Does it catch every date format?

      A. No — to avoid false positives, slash/hyphen Western dates (like 2024/1/2) are only matched when the year is between 1900 and 2099, so things like invoice or product codes aren't mistaken for dates. Abbreviated era dates with an implausibly large year number (like R150.1.1) are skipped too. Always check the preview or the detected list before relying on the result.

      Q. Is my text or file uploaded anywhere?

      A. No. Everything is processed inside your browser on this device (only an anonymous, cookie-free page-view count for this site is sent, via GoatCounter).

      Q. In CSV mode, could it touch header rows or ID columns by mistake?

      A. Keep "Treat the first row as a header" checked to exclude row 1. For data cells, it only rewrites a cell when it finds something that looks like a real date, with the same false-positive guards described above — but it isn't perfect, so review the preview before downloading.
