「Wordファイルが重い」原因を診断：ファイル内訳チェッカー

Word(.docx)ファイルの容量を、画像・埋め込みオブジェクト・埋め込みフォントなどのパーツ別に内訳表示し、容量を押し上げている可能性が高い原因を順に挙げます。画像をトリミング（切り取り）しても元の画像データがファイルにそのまま残る問題も検出します。ファイルを開かず、ブラウザの中だけで診断します。

ここにWord(.docx)ファイルをドラッグ＆ドロップ、またはクリックして選択

1回に1ファイル。.docxのみ対応（.doc・パスワード保護は読み込めません）。ファイルは選択した端末の中だけで処理されます。

全体の内訳

「ZIP内サイズ」は.docxファイル自体の容量（メール添付などで実感する重さ）に直結する数値です。

    数値から機械的に推測した「可能性」であり、断定ではありません。

      使い方とよくある質問

      1. 上の枠にWord（.docx）ファイルをドラッグ＆ドロップするか、クリックして選びます。
      2. 「全体の内訳」でファイル容量の大まかな構成（画像・埋め込みオブジェクト・埋め込みフォントなどの数）を確認します。
      3. 「容量を押し上げている可能性が高い原因」を確認します（スコアが高い順）。
      4. トリミングされた画像が見つかった場合は、専用の一覧で該当する画像ファイル名と、元データが残っている可能性のあるおおよその容量を確認できます。
      5. 「パーツ別の容量一覧」で、本文・ヘッダー・フッター・画像・埋め込みオブジェクトなどの実際のサイズを細かく確認できます。必要ならCSVでダウンロードできます。

      Q. このツールにファイルをアップロードしても安全ですか？

      A. はい。ファイルはサーバーに送信されず、すべてこのページを開いているブラウザの中だけで読み込みが行われます（サイト全体の閲覧数をCookieなし・匿名で数えるGoatCounterの通信のみ発生します）。ファイルの内容を書き換えたり保存したりすることもありません。

      Q. 「Wordファイルが重い」原因はどうやって調べていますか？

      A. .docxファイルの実体はZIP形式で、内部に本文・画像・埋め込みオブジェクト・埋め込みフォントなどの部品が別々のファイルとして入っています。Word自身には画像ごとの容量を一覧で見る機能がありません。このツールはZIPの目次（セントラルディレクトリ）から各部品の実際のサイズを読み取って内訳を作り、容量や重さに関わりやすい箇所を順に挙げます。

      Q. 「画像をトリミングしても元データが残る」とはどういうことですか？

      A. Wordで画像を「トリミング」すると、画面上は切り取られたように見えますが、実際には画像データそのものは削除されず、「どこを表示するか」という範囲情報（切り取り位置）だけが別に記録され、元の画像は丸ごとファイルの中に残ります。大きな写真の一部だけを使うつもりで大胆にトリミングすると、見えている部分よりはるかに大きい元画像のデータがそのままファイルに残り続け、容量を圧迫します。このツールは、本文・ヘッダー・フッター・脚注・文末脚注にある画像の切り取り範囲（DrawingMLのsrcRect）を調べ、切り取られた面積の比率から「元データが残っている可能性が高い画像」とその推定容量を一覧表示します。Word側で完全に削除するには、画像を選んで「図ツール」→「图の圧縮」で「トリミングした領域を削除する」にチェックを入れて保存し直す必要があります（このツール自体はファイルを書き換えません）。

      Q. 「埋め込みフォント」が原因になるのはなぜですか？

      A. Wordの「ファイル」→「オプション」→「保存」で「フォントをファイルに埋め込む」を有効にすると、使用した日本語・欧文フォントの実データ（1つあたり数百KB〜数MBになることがあります）がファイルの中にそのまま保存されます。社外の人が同じフォントを持っていなくても見た目が崩れないようにするための機能ですが、フォントの数や文字種によってファイルサイズを大きく押し上げる原因になります。

      Q. 画像と埋め込みオブジェクトの違いは何ですか？

      A. 画像は本文に貼り付けた写真・図などです。埋め込みオブジェクトは、Excelの表やグラフの元データ、PDF・別のWordファイルなどを、アイコンや画面表示のまま貼り付けたものです。1つあたりの容量が画像より大きくなりやすいです。

      Q. 対応しているファイル形式は？ファイルサイズの上限はありますか？

      A. Word 2007以降の.docx形式に対応しています。古い.doc形式や、パスワードで保護されたファイルは読み込めません。ファイルはブラウザのメモリ上で処理するため、非常に大きいファイル（数百MB以上）では、診断自体に時間がかかったりブラウザが重くなったりすることがあります。

      Q. 結果通りに直せば必ずファイルが軽くなりますか？

      A. このツールは原因の「可能性」を挙げるだけで、ファイルを書き換えることはしません。実際に軽くするには、トリミング領域の完全削除、画像自体の圧縮、埋め込みフォント・埋め込みオブジェクトの整理などをWord側で行う必要があります。原因が1つに絞れないファイルもあります。

      How to use & FAQ

      1. Drag and drop a Word (.docx) file into the box above, or click it to choose one.
      2. Check the overall breakdown: rough counts of images, embedded objects and embedded fonts.
      3. Review the ranked list of likely causes (highest score first).
      4. If cropped images are found, a dedicated list shows each image's file name and the estimated size of the original data that may still be sitting in the file.
      5. Use the detailed per-part table (body, headers, footers, images, embedded objects, …) for exact sizes, and download it as CSV if needed.

      Q. Is it safe to use this on my files?

      A. Yes. Files are never uploaded to a server — everything is read inside your browser (only an anonymous, cookie-free page-view count for this site is sent, via GoatCounter). The file's contents are never modified or saved anywhere.

      Q. How does this figure out why a file feels heavy?

      A. A .docx file is really a ZIP archive containing separate parts for the body text, images, embedded objects, embedded fonts and more. Word itself has no built-in way to see a per-image size breakdown. This tool reads the ZIP's central directory to get each part's real size, then ranks the factors most likely adding to the total.

      Q. What does "cropped image, original data still present" mean?

      A. When you crop a picture in Word, it only looks cut on screen — the underlying image data isn't actually trimmed. Word just stores a separate "which part to show" rectangle (DrawingML's srcRect) and keeps the full original image inside the file. If you aggressively crop a large photo down to a small detail, the much larger original keeps taking up space. This tool checks every image's crop rectangle in the body, headers, footers, footnotes and endnotes, and lists images where a large share of the original was cropped away but is still stored, along with an estimated size. To actually discard it in Word, select the image, go to Picture Format → Compress Pictures, and check "Delete cropped areas of pictures" before re-saving (this tool itself never rewrites your file).

      Q. Why would an embedded font add to the size?

      A. Turning on "Embed fonts in the file" under Word's File → Options → Save stores the actual font data — sometimes several hundred KB to a few MB per font — directly inside the document, so it displays correctly even if the recipient doesn't have that font installed. The number of fonts and the character sets they cover can add up quickly.

      Q. What's the difference between images and embedded objects?

      A. Images are pictures pasted into the body. Embedded objects are things like an Excel table or chart's source data, a PDF, or another Word file pasted in and shown as an icon or preview — these tend to be larger than a typical image.

      Q. Which formats and sizes are supported?

      A. Word 2007+ .docx files. The older .doc format and password-protected files are not supported. Everything runs in your browser's memory, so very large files (several hundred MB) may take a while or make the browser sluggish during diagnosis.

      Q. If I act on the results, is the file guaranteed to get smaller?

      A. This tool only reports likely causes — it never modifies your file. Actually shrinking it requires deleting cropped image data, compressing images, or cleaning up embedded fonts/objects in Word itself. Some files don't have one single cause.
